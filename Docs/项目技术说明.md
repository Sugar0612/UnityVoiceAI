# Unity VoiceAI 数字人语音助手 —— 技术说明

> 语音交互数字人一体机：唤醒词免按键唤醒 → 录音 → 云端语音识别 → DeepSeek 生成回答 → 免费女声朗读 → 数字人同步口型动画。
> 已在两种硬件上部署验证：PICO 一体机（Android 侧载）与 Rockchip 平板 n301_tablet（Android 11 工厂定制 ROM）。

---

## 一、总体架构

```
[麦克风常驻监听] WakeWordDetector（sherpa-onnx 离线关键词检测，说"何夕月"）
        ↓ 命中
[应答"我在"] 免费女声 TTS（预合成缓存，秒出） → 打开录音麦克风
        ↓
[录音] Microphone 采样 + RMS 静音检测（开口判定/静音自动结束/最长时长）
        ↓
[语音识别 STT] 优先 Android 系统识别（不可用自动降级）→ 讯飞方言大模型（主）→ 硅基流动 SenseVoice（备）
        ↓ 文本
[大模型] DeepSeek chat/completions（SSE 流式接收）
        ↓ 回答文本
[语音合成 TTS] 免费女声：Edge 晓晓（主）→ 讯飞小燕（降级）；可选 MiniMax 声音复刻
        ↓ PCM → AudioClip
[播放 + 数字人] AudioSource 朗读；动画 "Take 001" 循环播放，停止定格第 0 帧（闭嘴）
[守护] 崩溃看门狗（独立进程）+ 开机自启（HOME 桌面 / BOOT_COMPLETED 双通道）
```

- 引擎：Unity 6000.3.20f1（URP），IL2CPP / arm64-v8a，Target API 36、Min API 25
- 包名：`com.parasiticwasps.voiceai`
- 总控脚本：`Assets/Scripts/VoiceAI/VoiceAIController.cs`（状态机 Idle/Listening/Thinking/Speaking，全部子系统在此汇聚）

## 二、核心模块与实现方式

### 1. 唤醒词（免按键交互）
- 文件：`WakeWordDetector.cs`、`SherpaOnnxNative.cs`
- 技术：**sherpa-onnx 离线关键词检测（KWS）**，模型为 zipformer 三件套（encoder int8 / decoder / joiner）+ `keywords.txt`，位于 `Assets/StreamingAssets/KwsModel/`
- 原生库：`Assets/Plugins/Android/arm64-v8a/libsherpa-onnx-*.so`，通过 P/Invoke 封装（`SherpaOnnxNative.cs`）
- 常驻麦克风监听；命中回调 `OnWakeWordDetected`；`wakeOnlyWhenIdle` 防止对话中误触发
- 录音麦克风与监听麦克风互斥：唤醒命中后先关监听再开录音（Android 两个 AudioRecord 冲突）

### 2. 录音与端点检测
- `VoiceAIController`：`Microphone.Start` 录制，滑动窗口计算 RMS
- 双阈值：`speechStartRms`（连续超阈值才算真正开口）→ `silenceRmsThreshold`（开口后连续静音自动结束）→ `maxRecordSeconds` 兜底
- 底噪自校准：录音开始先采样环境底噪再定静音线
- 唤醒后 N 秒未说话自动取消（`noSpeechTimeoutSeconds`）

### 3. 语音识别（STT）
| 通道 | 文件 | 协议 | 说明 |
|---|---|---|---|
| Android 系统识别 | `AndroidSpeechRecognizer.cs` | 平台 API | 国行 ROM 内置引擎，免网络；不可用自动降级 |
| 讯飞方言大模型（主） | `IflytekSttClient.cs` | WebSocket `wss://iat.cn-huabei-1.xf-yun.com/v1` | `domain=slm`、`accent=mulacc`（23 种方言含陕西话）；流式 40ms 分帧上传；HMAC-SHA256 鉴权拼 URL |
| 硅基流动（备） | `CloudSttClient.cs` | HTTP multipart，OpenAI 兼容 `/v1/audio/transcriptions` | 模型 `FunAudioLLM/SenseVoiceSmall`（免费） |

- 鉴权实现：`BuildAuthUrl` —— `host/date/request-line` 拼接后 HMAC-SHA256(APISecret) → Base64 authorization 参数（`date` 为 RFC1123 GMT）
- 降级链由 `VoiceAIController.BuildSttRoutine/TryFallbackStt` 驱动（`provider: 2=讯飞, 0=OpenAI兼容`）

### 4. 大模型（DeepSeek）
- 文件：`DeepSeekClient.cs`
- `POST https://api.deepseek.com/chat/completions`，`stream=true` SSE 流式接收，逐字上屏（现在文字 UI 隐藏，仅内部消费）
- 人设 prompt 在场景序列化字段 `deepSeek.personaPrompt`（医院医师助手"何夕月"），含安全约束（急症建议 120 等）

### 5. 语音合成（TTS）—— 三供应商 + 自动降级
| 供应商 | 文件 | 接口 | 声音 | 费用 |
|---|---|---|---|---|
| **Edge TTS（首选）** | `EdgeTtsClient.cs` | WSS `speech.platform.bing.com`（`Sec-MS-GEC` 令牌 = Windows FILETIME 取整 5 分钟窗口 + 令牌 SHA256） | `zh-CN-XiaoxiaoNeural` 晓晓女声 | 免费无账号 |
| **讯飞 TTS（降级）** | `IflytekTtsClient.cs` | WSS `wss://tts-api.xfyun.cn/v2/tts`（同讯飞账号鉴权） | `xiaoyan` 小燕女声 | 免费试用额度 |
| MiniMax 声音复刻（可选） | `CloudTtsClient.cs` | HTTP `POST /v1/t2a_v2`，返回 hex 编码裸 PCM16 | 复刻音色 `TSY_voice01` | 按字符收费 |
| 系统 TTS | `AndroidTextToSpeech.cs` | Android TextToSpeech | 依赖 ROM | 免费（目标设备无引擎，仅作后备） |

- 统一入口 `VoiceAIController.SynthTts()`：`useFreeTts=true` 时先 Edge，失败自动降级讯飞
- 音频管线：服务器返回 **raw PCM16LE** → short→float 解码 → `AudioClip.Create` + `SetData`（无需 MP3 解码器）
- 唤醒应答"我在"：启动时 `PreSynthFreeAck()` 预合成并缓存（兼作设备网络自检），唤醒秒出声
- MiniMax 专属保活：`TryKeepAlive`（闲置 5 天自动合成"。"刷新 7 天删除线）+ 声音被删自动重克隆（`RecloneAndRetry`，样本在 `StreamingAssets/VoiceSample/`）；免费模式自动跳过
- 朗读期间：轮询 `IsSpeaking()` + 持续安静 0.3s 才复位（防个别机型 `onUtteranceCompleted` 误触发/估算超时导致"人没说完动画先停"）

### 6. 数字人（anim_shuzirenbangding03）
- 模型：`Assets/Model/anim_shuzirenbangding03.fbx`，**Legacy 动画导入**（单片段场景最稳，实例自动获得 Animation 组件）
- 场景绑定：`VoiceAIController.digitalHuman` 字段（留空自动按名查找）
- 状态联动 `UpdateDigitalHumanAnim`：
  - 进入 `Speaking` → `DhPlayTalk()`：`speed=1, time=0` 从第 0 帧循环播放
  - 离开说话态：若 TTS 仍实际出声（`IsTtsAudiblyPlaying` = AudioSource 在播 || 系统 TTS 在说）不停，等真正安静
  - 停止 → `DhFreezeAtFrame0()`：`speed=0, time=0, Sample()` **定格第 0 帧**（闭嘴姿态）——避免 `Stop()` 回退绑定姿态造成嘴停在半张
  - `Update()` 兜底：非说话态且彻底安静后补定格
- 实测数据：该片段驱动 192 个面部关节；停止复位后 1351/1351 关节精确回到第 0 帧

### 7. UI / 交互
- `hideTalkButton=true`：启动即隐藏"点击说话"按钮（场景里也已禁用，双保险）
- `hideDialogueText=true`：隐藏"你说：/AI："对话文字，仅保留顶部状态条（错误提示经 `RaiseError` 走状态栏）
- 边缘流光特效（`EdgeGlowEffect.cs`，彩虹液态流光）：`enableEdgeGlow` 默认 **false**——全屏 RawImage 逐帧着色 + Bloom 后处理在低端 GPU（Rockchip）上掉帧严重；场景 Volume 的 Bloom 也已关闭

## 三、Android Kiosk 常驻方案（重点）

**目标：开机自动进入应用；应用崩溃自动拉起。** 两种设备的行为差异很大，最终采用"HOME 桌面 + 广播接收器"双通道。

### Java 插件（Unity 源码插件，位于 `Assets/Plugins/Android/VoiceAIKiosk/.../kiosk/`）
| 类 | 职责 |
|---|---|
| `BootReceiver.java` | 收到 `BOOT_COMPLETED`/`MY_PACKAGE_REPLACED` 后拉起主界面（`getLaunchIntentForPackage`）并启动看门狗服务 |
| `WatchdogService.java` | **独立进程 `:watchdog`** 的前台服务（START_STICKY）：每 2 秒用 `getRunningAppProcesses` 检查主进程是否存活，连续 2 次缺失即 `getLaunchIntentForPackage` 重新拉起（约 4 秒恢复） |
| `Kiosk.java` | Unity→Java 桥：`startWatchdog(Activity)`，应用每次启动都会拉起看门狗 |
| `CrashTestReceiver.java` | 测试工具：广播 `com.parasiticwasps.voiceai.CRASH_TEST` 即杀主进程，用于验证看门狗 |

- C# 侧：`StartKioskWatchdog()` 经 `AndroidJavaClass` 调用 `Kiosk.startWatchdog`（UNITY_ANDROID 且非编辑器）

### 自定义 Main Manifest（`Assets/Plugins/Android/AndroidManifest.xml`）
- 显式声明 `UnityPlayerActivity`（Unity 6 自定义清单可能不自动注入启动入口），并加 **HOME + DEFAULT 类别**：系统开机必定启动桌面，这是绕过 ROM 广播限制的保险通道
- 关键合并点：Unity 库模板也声明了同名 Activity，必须 `tools:node="replace"` 才能让 HOME 类别生效
- 权限：`RECEIVE_BOOT_COMPLETED`、`FOREGROUND_SERVICE(_SPECIAL_USE)`、`POST_NOTIFICATIONS`、`SYSTEM_ALERT_WINDOW`（Android 10+ 看门狗后台拉起界面的豁免条件，需 `appops set ... allow`）、`RECORD_AUDIO`、`INTERNET`
- 服务声明：`android:process=":watchdog"` + `foregroundServiceType="specialUse"`（含 PROPERTY_SPECIAL_USE_FGS_SUBTYPE）

### 两台设备的实测差异（重要经验）
| 现象 | PICO 一体机 | Rockchip n301 平板（Android 11 工厂 ROM） |
|---|---|---|
| BOOT_COMPLETED 广播 | 正常送达 | **ROM 禁止为投递广播启动第三方进程**（日志：`Background execution not allowed`），接收器永远收不到 → 依赖 HOME 通道 |
| `pm grant` 运行时权限 | 被拒（但侧载应用自动放行麦克风） | 被拒 → 改用 **`adb install -r -g`** 安装时授权 |
| 安装后直接启动 | 正常 | 偶发 Unity 引擎初始化卡死 → **重启一次即恢复**（部署脚本含重启步骤） |
| 系统 TTS | 无引擎/不可用 | **完全没有任何 TTS 引擎** → 必须云端 TTS |
| 电池白名单 | 需要 | `dumpsys deviceidle whitelist +pkg` 可用 |

## 四、打包与部署

### 打包（两种方式）
1. **编辑器内**：MCP For Unity（`manage_build`）
2. **命令行（无界面，当前主用）**：
   ```
   D:\Engine\Unity\6000.3.20f1\Editor\Unity.exe -batchmode -quit ^
     -projectPath E:\ParasiticWasps\UnityVoiceAI ^
     -executeMethod CliBuild.BuildAndroid -logFile Builds\cli_build.log
   ```
   入口在 `Assets/Editor/CliBuild.cs`（`BuildPipeline.BuildPlayer` → `Builds/VoiceAI.apk`，失败 Exit(1)）。
   注意：**项目被 Unity 编辑器打开时无法命令行打包**（项目锁）。

### 部署包（`Deploy/`，整夹拷贝到部署机）
| 文件 | 作用 |
|---|---|
| `VoiceAI.apk` | 最新构建产物（约 51MB，构建工具链会报 900MB+ 那是含中间产物的总大小） |
| `install_app.bat` | 一键安装（**GBK 编码 + CRLF**，cmd 中文不乱码；bat 文件绝不能存 UTF-8 中文） |
| `adb\adb.exe + 两个 dll` | 自带 adb，目标机无需安装环境 |

`install_app.bat` 流程：找 adb（自带→PATH）→ 等设备 60 秒 → `install -r -g`（**`-g` 安装时自动授予全部运行时权限**，绕开 ROM 限制）→ `pm grant`/`appops`/电池白名单（失败静默）→ `cmd package set-home-activity`（开机直达的关键）→ 音量调满 → 启动 → 验证主/看门狗双进程。

### 部署后自测命令
```bat
:: 崩溃自动重启测试（约 4 秒内拉回）
adb shell am broadcast -a com.parasiticwasps.voiceai.CRASH_TEST
:: 开机自启测试
adb reboot
```

## 五、运维与注意事项

1. **API Key 管理**：DeepSeek/讯飞/硅基流动/MiniMax 的 key 明文存于 `SampleScene.unity` 的序列化字段。仓库为私有可接受；若转公开需先轮换全部 key。
2. **MiniMax 克隆音色 7 天未用会被删**：`autoKeepAlive=5天` 自动保活 + 自动重克隆。当前默认走免费女声（`useFreeTts=true`），MiniMax 仅作备选，不触发保活也不产生费用。
3. **讯飞免费额度**：STT（方言大模型）与 TTS（在线语音合成）各有新用户免费资源包，用尽后按量计费，控制台 [console.xfyun.cn](https://console.xfyun.cn) 查看/领取。
4. **DeepSeek 按 token 计费**：[platform.deepseek.com](https://platform.deepseek.com) 查账单。
5. **Edge TTS 为非官方接口**：国内部分网络不可达（本平板不可达，自动降级讯飞）；若微软更新鉴权算法，改 `EdgeTtsClient.GenGecToken`/版本号。
6. **ROM 偶发抽风**：n301 平板安装后立即启动可能卡在 Unity 引擎初始化（`Context Type` 后无日志）——重启一次即恢复，部署流程已包含重启。
7. **工具脚本**（`Tools/`）：
   - `unity_mcp.py`：绕过 MCP 桥接端口漂移，直连 Unity 编辑器的 HTTP MCP（探测 8080→8083 等）
   - `make_deploy_bat.py`：重新生成 GBK 编码的 `Deploy/install_app.bat`
   - `install_and_setup.bat`：本机开发用安装脚本
   - `watchdog.ps1`：PC 侧备用看门狗（设备长连电脑时的双保险）
   - `auto_build_and_install.py`：Unity 被占用时的自动等锁打包+部署守候脚本
